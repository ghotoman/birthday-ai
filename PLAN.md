# BirthdayAI — План разработки

## Концепция

Мобильное приложение (iOS + Android), которое позволяет за <3 минуты сгенерировать уникальное поздравление с днём рождения (текст + открытка) с помощью нейросетей. Импорт контактов из соцсетей и календаря, умные напоминания, персонализация через атрибуты и тон.

---

## 1. Технический стек

### Frontend (мобильное приложение)
| Компонент | Выбор | Почему |
|-----------|-------|--------|
| Фреймворк | **React Native (Expo)** | Один кодбейз на iOS/Android, быстрый старт, OTA-обновления через EAS Update |
| Навигация | React Navigation v7 | Де-факто стандарт, поддержка deep links |
| Стейт | Zustand + React Query | Zustand — лёгкий локальный стейт; React Query — серверный стейт, кэширование, оптимистичные обновления |
| UI Kit | Tamagui или Nativewind (Tailwind для RN) | Производительность + кроссплатформенность + красивый дизайн из коробки |
| Анимации | Reanimated 3 + Moti | Плавные gesture-based анимации, микроинтеракции |
| Хранение | MMKV (быстрый key-value) + SQLite (expo-sqlite) | MMKV для настроек, SQLite для контактов/истории |
| Пуши | expo-notifications + Firebase Cloud Messaging | Кроссплатформенные push-уведомления |

### Альтернатива: Flutter
Если важна максимальная нативная производительность анимаций — Flutter + Riverpod. Но React Native с Expo сейчас сопоставим и имеет более зрелую экосистему для интеграций с соцсетями.

### Backend
| Компонент | Выбор | Почему |
|-----------|-------|--------|
| Runtime | **Node.js (Fastify)** или **Python (FastAPI)** | Fastify — если бэкенд лёгкий (проксирование API). FastAPI — если будет своя ML-логика |
| БД | PostgreSQL + Prisma ORM | Реляционные данные (пользователи, контакты, история) |
| Кэш | Redis | Кэширование ответов нейросетей, rate limiting |
| Очереди | BullMQ (Redis-based) | Фоновая генерация открыток, отправка пушей |
| Auth | Supabase Auth или Firebase Auth | OAuth из коробки (VK, Google, Apple Sign-In) |
| Storage | S3 / Supabase Storage | Хранение сгенерированных открыток |
| Хостинг | Railway / Render / VPS | Для MVP; потом можно мигрировать на k8s |

### AI / Нейросети
| Задача | Сервис | Примечание |
|--------|--------|------------|
| Генерация текста | **OpenAI GPT-4o** / **Claude** / **YandexGPT** | Несколько провайдеров на выбор пользователя (или автовыбор лучшего) |
| Генерация открытки | **DALL-E 3** / **Midjourney API** / **Stable Diffusion (SDXL)** | DALL-E через OpenAI API проще всего; SD можно хостить самим для экономии |
| Fallback | Локальные шаблоны | Если API недоступен — готовые шаблоны с кастомизацией |

## 3. Экраны и UX-flow

### 3.1 Онбординг (первый запуск)
1. **Welcome** — 3 свайп-экрана с анимацией (Lottie):
   - "Никогда не забывай о дне рождения"
   - "Уникальное поздравление за 2 минуты"
   - "Подключи друзей из соцсетей"
2. **Авторизация** — Apple Sign-In / Google / VK / номер телефона
3. **Импорт контактов** — предложение подключить VK/OK/календарь (можно пропустить)
4. **Разрешение на пуши** — с объяснением зачем ("Напомним за 3 дня до ДР")

### 3.2 Главный экран (Home)
- **Ближайшие дни рождения** — горизонтальный карусель с аватарами и обратным отсчётом
- **Сегодня** — выделенная секция если у кого-то сегодня ДР, с кнопкой "Поздравить!" (CTA)
- **Быстрые действия** — "Добавить человека", "Импорт из соцсетей"
- **История поздравлений** — лента с предыдущими генерациями

### 3.3 Профиль контакта
- Имя, фото, дата рождения
- **Атрибуты** (теги): хобби, характер, внутренние шутки, прозвища, общие воспоминания
- **Тон по умолчанию**: тёплый / дружеский / формальный / саркастический / дерзкий
- **Группа**: семья / близкие друзья / коллеги / знакомые
- **Уровень уведомлений**: за 7 дней + за 1 день / за 1 день / в день / без уведомления
- История прошлых поздравлений этому человеку

### 3.4 Flow генерации поздравления (< 3 минуты)

**Шаг 1: Выбор получателя** (5 сек)
- Tap на человека из главного экрана или поиск

**Шаг 2: Быстрая анкета** (30-60 сек)
Серия swipeable-карточек с вопросами:
- "Какой тон?" → [Тёплый] [Весёлый] [Дерзкий] [Формальный]
- "Упомянуть что-то конкретное?" → текстовое поле (опционально)
- "Возраст — тема для шуток?" → [Да, жги] [Лучше нет]
- "Длина?" → [Коротко и ёмко] [Развёрнуто] [Стихи]
- "Формат?" → [Только текст] [Текст + открытка] [Только открытка]

Вопросы адаптируются на основе сохранённых атрибутов контакта. Если атрибуты заполнены — некоторые вопросы скипаются.

**Шаг 3: Генерация** (15-30 сек)
- Красивая анимация ожидания (не спиннер, а что-то тематическое — воздушные шары, конфетти)
- Параллельная генерация текста и открытки
- Стриминг текста (typewriter-эффект) как в ChatGPT

**Шаг 4: Результат и редактирование** (30-60 сек)
- Показ сгенерированного текста + открытки
- Кнопки: [Перегенерировать] [Подправить вручную] [Другой тон]
- Свайп для альтернативных вариантов (генерим 2-3 штуки параллельно)

**Шаг 5: Отправка / Сохранение** (10 сек)
- [Копировать текст]
- [Поделиться] → нативный share sheet (WhatsApp, Telegram, VK, SMS, и т.д.)
- [Скачать открытку]
- [Сохранить в историю]

### 3.5 Настройки
- Управление подключёнными соцсетями
- Настройки уведомлений (глобальные)
- Выбор предпочитаемой нейросети
- Тема оформления (светлая/тёмная/авто)
- Подписка / баланс генераций

## 4. Интеграции с соцсетями

### VK (ВКонтакте)
- VK ID OAuth 2.0
- API метод `friends.get` с полем `bdate` — даты рождения друзей
- `users.get` с полями `photo_200`, `first_name`, `last_name`
- Ограничение: дату рождения видно только если пользователь её не скрыл

### Одноклассники
- OK OAuth 2.0
- API метод `friends.get` → `users.getInfo` с полем `birthday`
- Аналогичные ограничения по приватности

### Календарь устройства
- `expo-calendar` — доступ к событиям типа "Birthday"
- iOS автоматически создаёт Birthday calendar из контактов
- Android — парсинг событий с ключевым словом "день рождения" / "birthday"

### Контакты устройства
- `expo-contacts` — поле `birthday` в контактах телефона

### Синхронизация
- Первичный импорт → сохранение в локальную БД
- Периодическая фоновая синхронизация (раз в неделю)
- Ручной re-sync по запросу
- Дедупликация по имени + дате рождения

## 5. Система уведомлений

### Уровни приоритета
| Группа | По умолчанию | Настраиваемо |
|--------|-------------|--------------|
| Семья | За 7 дней + за 1 день + в день | Да |
| Близкие друзья | За 3 дня + в день | Да |
| Друзья | За 1 день | Да |
| Знакомые | В день | Да |
| Коллеги | В день | Да |

### Формат пуша
- **За N дней**: "Через 3 дня у Маши день рождения! Подготовь поздравление заранее 🎂"
- **В день**: "Сегодня день рождения Маши! Поздравь за 2 минуты → [Поздравить]"
- Deep link на flow генерации с предзаполненным контактом

### Технически
- Firebase Cloud Messaging (cross-platform)
- Серверные scheduled jobs (cron) для отправки за N дней
- Локальные уведомления как fallback (expo-notifications scheduling)

## 9. Схема БД (ключевые таблицы)

```sql
-- Пользователь приложения
CREATE TABLE users (
    id UUID PRIMARY KEY,
    phone TEXT,
    email TEXT,
    name TEXT NOT NULL,
    avatar_url TEXT,
    premium_until TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT now()
);

-- Контакт (человек, которого поздравляем)
CREATE TABLE contacts (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    name TEXT NOT NULL,
    avatar_url TEXT,
    birthday DATE NOT NULL,
    group_type TEXT DEFAULT 'friend',  -- family, close_friend, friend, colleague, acquaintance
    notification_level TEXT DEFAULT 'day_before', -- week, 3days, day_before, same_day, none
    tone_default TEXT DEFAULT 'warm',  -- warm, funny, sarcastic, formal, roast
    source TEXT,  -- manual, vk, ok, calendar, contacts
    source_id TEXT,  -- ID в источнике для синхронизации
    created_at TIMESTAMPTZ DEFAULT now()
);

-- Атрибуты контакта (теги для персонализации)
CREATE TABLE contact_attributes (
    id UUID PRIMARY KEY,
    contact_id UUID REFERENCES contacts(id),
    category TEXT NOT NULL,  -- hobby, trait, memory, joke, nickname
    value TEXT NOT NULL
);

-- Сгенерированное поздравление
CREATE TABLE greetings (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    contact_id UUID REFERENCES contacts(id),
    greeting_text TEXT,
    card_image_url TEXT,
    tone TEXT NOT NULL,
    ai_provider TEXT NOT NULL,  -- openai, claude, yandexgpt
    prompt_used TEXT,  -- для дебага и улучшения
    questionnaire JSONB,  -- ответы на анкету
    year INT NOT NULL,  -- за какой год поздравление
    shared_via TEXT[],  -- ['whatsapp', 'telegram', 'copy']
    created_at TIMESTAMPTZ DEFAULT now()
);

-- Подключённые соцсети
CREATE TABLE social_connections (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    provider TEXT NOT NULL,  -- vk, ok
    access_token TEXT NOT NULL,
    refresh_token TEXT,
    expires_at TIMESTAMPTZ,
    last_sync_at TIMESTAMPTZ
);
```

## 11. Промпт-инжиниринг (пример системного промпта для генерации)

```
Ты — креативный копирайтер, специализирующийся на поздравлениях с днём рождения.

Контекст:
- Имя именинника: {{name}}
- Возраст: {{age}} (если указан)
- Кто поздравляет: {{sender_name}}
- Отношения: {{relationship}} (друг/коллега/мама/и т.д.)
- Тон: {{tone}} (тёплый/весёлый/саркастический/формальный/дерзкий)
- Атрибуты: {{attributes}} (хобби, черты характера, шутки, воспоминания)
- Формат: {{format}} (короткий/развёрнутый/стихи)
- Можно шутить про возраст: {{age_jokes_ok}}
- Дополнительный контекст от отправителя: {{custom_note}}

Правила:
1. Поздравление должно быть уникальным и личным
2. Используй предоставленные атрибуты органично
3. Соблюдай выбранный тон
4. Не используй клише ("счастья, здоровья, успехов" — только если это ирония)
5. Если тон дерзкий/саркастический — будь остроумным, но не обидным
6. Длина: короткий (2-3 предложения), развёрнутый (5-7 предложений), стихи (4-8 строк)
```

## 12. Ключевые UX-принципы

1. **Минимум шагов** — от открытия приложения до готового поздравления максимум 5 тапов
2. **Предзаполнение** — если атрибуты уже есть, анкета короче
3. **Анимации ожидания** — генерация не должна казаться долгой (skeleton, typewriter, конфетти)
4. **Haptic feedback** — вибрация на ключевых действиях
5. **Не блокировать** — если открытка генерируется долго, показать текст сразу
6. **Пустые состояния** — красивые empty states с CTA ("Добавь первого друга!")
7. **Тёплая палитра** — мягкие градиенты, скруглённые углы, friendly иллюстрации
8. **Dark mode** — обязательно, и не как afterthought

## 13. Риски и митигация

| Риск | Вероятность | Митигация |
|------|------------|-----------|
| API нейросети недоступен | Средняя | Fallback на другого провайдера, кэш популярных генераций, локальные шаблоны |
| VK/OK закроют API | Средняя | Не делать их единственным источником, фокус на ручном вводе + контакты телефона |
| Генерация слишком долгая | Низкая | Стриминг, параллельная генерация, UX-приёмы (анимации) |
| Пользователь не возвращается | Высокая | Push-уведомления, виджет на home screen с ближайшим ДР |
| Модерация контента | Средняя | Content filter на бэкенде, ограничение "дерзкого" тона |
